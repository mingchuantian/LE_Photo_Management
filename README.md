# LE 商品图工作室

本地 Python + Flask 应用：商品批量上传 → Poof 抠图 → 单模板调整位置、大小、旋转 → 确认并套用全部模板 → OpenAI 光影处理 → 挑选与下载。

## 启动

当前电脑已配置 `.venv`，双击 **start.bat**，或在项目目录运行：

```powershell
.\start.ps1
```

打开 <http://127.0.0.1:5000>。关闭启动窗口即可停止服务。应用使用 Waitress，绑定本机 127.0.0.1；一次只启动一个实例。

其他电脑需要 Python 3.11–3.13，然后运行 `setup.ps1`。可以用 `setup.ps1 -PythonPath 'C:\path\to\python.exe'` 指定标准 CPython。不需要 Node 或前端构建。

## 使用

1. 在「背景模板」批量上传背景。系统自动修正 EXIF 方向，等比缩放、居中裁切为 **1080 × 1350**，透明区域以白色补底，不拉伸。较宽或较高图片的两侧或上下会被裁切；上传后点击模板检查。
2. 根目录放好 `poof.bg_key`，然后在「批量工作台」上传商品。后台调用 Poof Background Removal API，返回透明 PNG。抠图完成后停在「待确认摆放」，不会自动生成全部模板组合。已有透明图保留，商品卡片或单图流程中可选择「用 Poof 重新抠图」或「用 Photoroom 重新抠图」。
3. 为商品选择五档默认尺寸，点击「预览并调整摆放」。在一个背景上拖动、调整宽度、旋转或输入中心位置；方向键移动 1px，Shift + 方向键移动 10px。预览会返回与最终合成一致的服务器渲染。确认后，位置、大小和旋转套用全部模板；可「确认并继续下一个」依次处理商品。新增模板只为已确认商品补齐。每个商品只缩放、旋转并保存一次透明图层，默认 4 个线程并行处理背景合成；进度会实时显示在商品组合卡片及弹窗中，已完成图片可先勾选。一个模板失败不会阻断其他模板，重试仅补齐缺失组合。改尺寸或重新抠图后，需要重新确认摆放。
4. 「已确认的模板组合」每个商品只显示一张卡片。点击「选择组合」，在该商品的弹窗里多选、搜索背景或筛选尚未生成的组合；可从下拉菜单切换商品，各自的选择都会保留。弹窗可处理本商品所选，也可完成选择后回工作台统一处理多个商品。每张 **1–10 个结果，默认 3**。显示预计成品总数；处理过程中可继续查看与操作。所有 AI 批次共用 20 个工作线程，同一批和不同批次的组合均可并行调用 API，合计最多 20 个请求同时运行；剩余项目等待空位。每个组合仍按选择的 n（1–10）一次请求，不改变模型、Prompt 或其他设置。完成的结果立即保存，逐项进度独立更新，单张失败不阻断其他请求。API 限流仍遵循账户限制，不自动重复收费请求，可手动重试失败项。
5. 「成品图库」按上传原图显示商品分组，打开每个商品的弹窗查看所有背景、所有生成批次和旧版本的结果。可搜索背景、选两张并排放大比较、查看完整图片流程，以及「设为本商品最佳」。每个商品最多一张最佳，选择保存在 SQLite，刷新或重启后保留。可上一个/下一个商品连续挑选，最后「打包下载每个商品最佳」；勾选多张和「下载所选」仍可使用。商品透明 PNG 和合成预览也支持批量下载。

点击商品、预览或成品可查看单图 pipeline：原始照片、透明商品、各模板合成（包括旧尺寸版本）及对应生成结果。单图支持原尺寸查看和 PNG 下载。

## 第一版摆放规则

| 尺寸 | 包的可见宽度 / 画布宽度 |
| --- | --- |
| 小 | 40% |
| 小中 | 52.5% |
| 中 | 65% |
| 中大 | 77.5% |
| 大 | 90% |

商品水平居中，按透明图 **所有 alpha > 0 的像素** 测量边界，包括半透明边缘。等比缩放后再次检查非透明边界，确保最底部像素距离画布底部约 1/8（1080 × 1350 画布留 169 px 底部空间）。五档控制可见商品宽度；特别高的商品会等比缩小到能完整显示的最大尺寸，避免裁断包或提手。这只是默认初始摆放。单模板预览中可以自由调整位置、等比缩放和旋转；界面会避免商品超出画面，服务端也检查边界。所有模板采用相同的归一化中心坐标、宽度和旋转角度。合成只包含缩放、旋转和摆放，没有额外生成、光线或阴影处理。

后续比例在 `imaging.py` 的 `SIZE_WIDTHS`、`BASELINE` 调整。服务启动会检查摆放规则的版本，变更后仅为已确认商品补齐预览，已有合成与成品作为历史记录保留。升级到分步流程后，旧商品需先确认摆放，旧图仍在单图流程中可查看。

## Poof

`poof_service.py` 调用官方接口 `POST https://api.poof.bg/v1/remove`，使用 `x-api-key` 和 multipart `image_file`，输出 PNG RGBA，`size=full`、`crop=false`，不设置背景颜色。环境变量 `POOF_API_KEY` 优先，其次根目录 `poof.bg_key`（纯 key 或 `POOF_API_KEY=...`）。key 只在服务端读取，已加入 `.gitignore`。

最长边超过 6000px 时等比缩小，确保不超过 36MP。输入优先使用无损 PNG；超过 20MB 时尝试无损 WebP，仍超过限制则提示缩小原图。返回图片保留原始透明边缘，不套用旧 Photoroom 的雾状残留清理规则。请求超时、限流或失败不会自动重复提交，也不会回退调用 Photoroom；重试由用户决定。

现有透明图、摆放、模板组合和成品保留。新上传默认使用 Poof。商品卡片和单图流程可明确选择 Poof 或 Photoroom 重新抠图；Photoroom 使用根目录 `photoroom_key` 或环境变量 `PHOTOROOM_API_KEY`。两种服务都从保存的上传原图读取，不会对已经抠好的图再次抠图。失败重试沿用该次选择的服务，任务记录保存服务选择。重新抠图后需要确认摆放；原透明图和旧版本保留供历史成品还原。旧图的来源仍显示 Photoroom。

[官方 Poof 抠图接口文档](https://docs.poof.bg/api-reference/remove-background)

## OpenAI

根目录 `openai_key` 支持纯 key，也支持 `OPENAI_API_KEY=...`；环境变量 `OPENAI_API_KEY` 优先。key 仅在服务端读取，不发送给浏览器。`.gitignore` 已排除 key、数据、环境及日志。

`ai_service.py` 保存用户原始 prompt 和以下设置，只有 `n` 动态变化：

```python
model="gpt-image-2.5-sunburst-2026-09-08"
size="auto"
quality="max"
background="auto"
moderation="auto"
```

Python SDK 使用 `client.images.edit`（单数）。`moderation` 经 `extra_body` 原样传给 API，不增加 mask 或其他模型参数。[官方 Image Edit 文档](https://developers.openai.com/api/reference/python/resources/images/methods/edit)

API 仍保留 `size="auto"`。每次合成都会保存生成前的透明商品图层快照。AI 返回后，将其整个背景画面缩放到 **1080 × 1350**，再按合成时完全相同的坐标、尺寸、旋转角度和透明度覆盖原商品，确保最终成品的包身纹理来自原照片。AI 原始结果单独保留，单图 pipeline 的「AI 成品」阶段可切换「商品还原成品 / AI 原始结果」并分别下载。默认图库与批量下载使用已还原商品的成品。

升级前已有成品也会自动在本地还原商品；覆盖使用各自原合成记录的位置和大小，不会按新尺寸移动旧结果中的商品，也不会重新请求 OpenAI。商品的透明部分保留 AI 背景与阴影。

## 存储与失败处理

所有资料持久化在 `data/studio.sqlite3` 和 `data/media/`。备份整个 `data` 文件夹即可。模板与商品移除属于隐藏操作，不物理删除历史文件；模板删除不会影响已有成品。原始上传会修正 EXIF 方向并以无损 PNG 存档在 `data/media/originals/`；保留解码后的原始照片像素，不保证保留上传文件的原始压缩编码或元数据。可在单图流程的「原始照片」查看和下载。重新抠图不覆盖原图。

任务进度、逐项错误、生成时的 prompt/参数记录在 SQLite。一个项目失败不影响其他项目；可重试失败项目。服务重启后未完成任务标为中断，不自动重新提交 AI 请求；API 超时也不自动重试，避免重复计费。手动重试会再次调用 API，超时或中断的请求可能已经在 OpenAI 端完成。

支持 JPG、PNG、WebP；单张最多 30 MB，解码最多 4000 万像素，每次最多 100 张，总请求最多 256 MB。HEIC 需先转成 JPG。长时间运行后，大量图片及历史版本会占用磁盘空间。

可选环境变量：`PORT`（默认 5000）、`PHOTO_DATA_DIR`（数据目录）、`POOF_API_KEY`、`PHOTOROOM_API_KEY`、`OPENAI_API_KEY`、`PHOTO_COMPOSE_WORKERS`（默认 4，范围 1–8，控制本地背景合成线程数）。服务面向本机使用，不包含多用户登录。
